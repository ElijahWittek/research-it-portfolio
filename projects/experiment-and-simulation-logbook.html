Experiment and Simulation Logbook

A local command-line application for structured documentation, filtering, persistent storage, and export of experiment and simulation run records.

Back to Projects

Problem

Experiment and simulation runs can quickly become difficult to track when parameters, associated data files, result summaries, and processing states are documented inconsistently.

A consistent data model is therefore useful for assigning information to individual runs and maintaining a traceable overview.

Solution

The application provides a local command-line logbook with a fixed data model and persistent JSON storage. Entries can be created, listed, filtered, marked as completed, and exported as CSV.

The application documents experiment and simulation runs but does not execute simulations, experiments, or scientific calculations itself.

Key Features

  • Create new logbook entries through an interactive command-line dialog
  • List all entries with complete stored information
  • Filter entries by status
  • Search entry titles using case-insensitive partial matching
  • Mark open entries as completed
  • Export the complete logbook as CSV

Technical Structure

The application is divided into modules with separated responsibilities for command handling, application logic, validation, persistence, and export:

  • main.py provides the module entry point and starts the CLI.
  • cli.py defines the parser, six command handlers, interactive input, and terminal output.
  • logbook.py contains entry creation, ID generation, sorting, filtering, and status transition logic.
  • validation.py validates user input and the complete stored data model.
  • persistence.py loads and saves the JSON logbook.
  • export.py formats parameters and exports the logbook as CSV.

The completed project contains 98 automated pytest tests. Ruff completed without findings in the final project state.

Repository-based command:

PYTHONPATH=src python -m experiment_and_simulation_logbook.main <command>

Data Model & Persistence

Each logbook entry contains eight defined fields: identifier, title, creation date, parameters, status, result summary, data-file reference, and notes.

The complete logbook is stored locally as UTF-8 JSON. Changes are persisted after successful creation or status updates. CSV export provides a separate, derived overview of the stored entries.

Known Limitations

  • The application is designed for local single-user operation.
  • The complete dataset is stored in a single JSON file.
  • Filtering is intentionally limited to simple status and title filters.
  • Entries cannot be generally edited or deleted.
  • Completed entries cannot be reopened.
  • The application does not execute experiments or simulations.
